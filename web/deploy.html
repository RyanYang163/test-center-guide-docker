部署指南

两种部署方式：一键脚本（推荐，全自动）与手动分步（理解每一步做了什么）。两种方式都需要先准备好一个 MySQL 与一个 Redis。

部署前准备

  • 一台可用的 Linux 或 NAS，已安装并启用 Docker 与 Docker Compose
  • 一个 MySQL 8 实例（可以是用容器另起的），并已知 host / 端口 / 库名 / 账号 / 密码
  • 一个 Redis 7 实例，并已知 host / 端口 / 密码
  • 一个空闲端口给前端使用，默认 19613（避开系统保留端口）
  • 镜像仓库地址与登录凭据 —— 由项目方提供

关于凭据：本指南与镜像内不内置任何仓库地址、账号或口令。镜像仓库地址与登录凭据请向项目方索取；部署助手生成的 .env 里也只填你自己环境的值。

不想手填参数的话，先到 部署助手 生成 .env，再回来按下方步骤执行。

方式一：一键脚本部署（推荐）

项目方随镜像提供一键脚本（deploy-image.sh + docker-compose-image.yml + .env.example）。脚本会依次完成：检测环境 → 登录镜像仓库拉取前后端镜像 → 交互式填写配置 → 创建网络并自动发现已有的 MySQL / Redis 容器 → 生成 .env → 创建数据库 → 启动后端并等待就绪 → 初始化数据库（迁移、定位策略、定时任务、通知模板、组件包）→ 创建管理员账号 → 启动全部服务。

# 在存放脚本的目录执行
chmod +x deploy-image.sh
./deploy-image.sh

交互式配置环节里，除了密码必须自己填，其余项确认无误直接回车使用默认值即可。脚本跑完会打印访问地址。

登录

看到部署完成的输出后，用浏览器打开 http://服务器IP:19613，出现登录页即为成功。首次登录后请立即修改默认管理员密码。

部署工具默认创建的管理员账号是 test / Admin123；如果你在部署时改过默认值，就以你填的为准。手动部署的实例用的则是下面第 7 步你自己传给 create_superuser 的账号。

方式二：手动分步部署

手动方式适合理解每一步在做什么，或者一键脚本在你的环境里跑不通时的兜底。完整命令可由 部署助手 按你的参数生成，下面是要点顺序：

1. 创建专用网络

前后端与 MySQL / Redis 必须在同一个 Docker 网络里，否则后端连不上数据库。

docker network create test_center_network

# 已有的 MySQL / Redis 容器也要接进来
docker network connect test_center_network <你的MySQL容器名>
docker network connect test_center_network <你的Redis容器名>

2. 登录镜像仓库并拉取镜像

docker login <镜像仓库地址>
docker pull <后端镜像>
docker pull <前端镜像>

3. 写配置文件

把部署助手生成的 .env 放到部署目录。关键项：SERVER_PUBLIC_IP、DB_*、REDIS_*、SECRET_KEY、WEB_PORT。文件含口令，记得 chmod 600 .env。

4. 创建数据库

docker exec -i <你的MySQL容器名> mysql -uroot -p'<MySQL密码>' -e \
  "CREATE DATABASE IF NOT EXISTS \`test-center\` \
   DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

5. 启动服务

数据库迁移由后端容器在启动时自动执行，不需要手动 migrate。首次启动要等迁移跑完，耐心一点。

docker compose --env-file .env up -d
docker compose ps

6. 初始化基础数据

这几条会装入定位策略、定时任务、通知模板、组件包与 Agent 文档索引 —— 缺一项功能就会不完整。

docker exec <后端容器名> python manage.py init_locator_strategies
docker exec <后端容器名> python manage.py init_system_tasks
docker exec <后端容器名> python manage.py init_notification_templates
docker exec <后端容器名> python manage.py load_component_pack
docker exec <后端容器名> python manage.py sync_agent_builtin_docs

7. 创建管理员账号

把用户名、邮箱、密码换成你自己的。之后就用这个账号登录，请记牢，并且不要用弱密码。

docker exec -i <后端容器名> python manage.py shell << 'EOSHELL'
from django.contrib.auth import get_user_model
User = get_user_model()
if not User.objects.filter(username='test').exists():
    User.objects.create_superuser('test', 'test@example.com', '换成你的强密码')
    print('管理员账号已创建')
else:
    print('管理员账号已存在')
EOSHELL

如果你用的是一键脚本或 TOS 应用，它会替你建 test / Admin123；首次登录后请立刻改掉。

部署验证

# 容器是否都起来了
docker compose ps

# 前端是否响应
curl -I http://<服务器IP>:19613/

# 后端日志（首次启动时看迁移进度）
docker logs -f <后端容器名>

浏览器打开 http://服务器IP:19613 看到登录页，说明部署成功。

常用运维命令

docker compose ps                  # 查看状态
docker compose logs -f backend     # 跟踪某个服务日志
docker compose restart backend     # 重启某个服务
docker compose down                # 停止并移除容器（不动数据卷）
docker compose up -d               # 重新拉起

升级怎么做？拉取新版本镜像后重建容器：docker compose pull && docker compose up -d。数据库迁移会在后端容器启动时自动执行。降级前请先备份数据库。
